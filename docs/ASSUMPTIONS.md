# Assumptions Log

Where the provider data is ambiguous, we record the assumption here and keep going. Each entry: what we assume, why, and what would change if we're wrong.

| ID | Assumption | Evidence / reason | If wrong |
|---|---|---|---|
| A-01 | The daily hit quota resets at 00:00 UTC. | Not stated by the provider. `info.hitsToday` is returned on every response. | The budget counter re-syncs from `info.hitsToday` on each call, so a wrong reset time only costs a few idle minutes. |
| A-02 | Error responses look like `{ status: "failure", reason: string }`, possibly with HTTP 200. | Provider convention; no failure was captured. | The adapter checks `status !== 'success'` and non-2xx, and fails closed either way. |
| A-03 | `dateTimeGMT` with time `00:00:00` means "time not published". | Many associate/women's fixtures in samples sit exactly at midnight UTC. | Only affects the UI ("Time TBC") and the pre-match market close time: markets close at the first `matchStarted=true` signal instead of a fixed time. |
| A-04 | Year-less series dates (`"Nov 21"`) take the year from `startDate`, rolling into the next year if the month is earlier than the start month. If `startDate` also lacks a year, use the 4-digit year in the series name, then the earliest match date. | Samples: `startDate "2027-10-02", endDate "Nov 21"`. | Display-only; no money decisions depend on series dates. |
| A-05 | Teams are identified by normalized name (`lowercase`, trimmed, `[XXX]` removed). | No team ids in any endpoint. | Two differently-spelled names for the same team would split stats. Admin can merge teams (alias list on `Team.aliases`). |
| A-06 | When `shortname` is missing we derive one (initials, ≤4 chars). | Franchise teams in sample 5 have no shortname. | Cosmetic. |
| A-07 | `cricScore[].id` is the same match UUID as in `currentMatches`/`matches`. | Same UUID format; no overlapping match in the captured samples to prove it. | Poller falls back to name+date matching and logs `CRICSCORE_ID_MISMATCH`. |
| A-08 | `cricScore` score strings look like `"98/9 (20)"`, and for Tests `"250 & 120/3 (40.2)"`. | Provider convention; all captured `t1s/t2s` are empty (fixtures). | Parser is tolerant. `cricScore` is used only as a change detector, never as a settlement source. |
| A-09 | A series with `matches: 0` and a year-less `startDate` is a shadow duplicate of a real series. | `eb59e02f` vs `4a708cd9` (same name, same dates). | Shadow series are hidden from users, not deleted. |
| A-10 | Player stat values can be `"45*"` (not-out high score) and `"-/-"` (no best figures). | `"-/-"` seen; `*` is standard cricket notation. | Parser falls back to `null` for anything unparseable. |
| A-11 | `series_squad` is a squad, not the playing XI. Top-batsman/bowler and player-runs markets use the squad, and selections not in the XI are voided at match start once the XI is known. | Squads have 12–15 players. | Standard bookmaker rule; documented in MARKET_RULES. |
| A-12 | Result text patterns: `"X won by N runs/wkts"`, `"(DLS method)"`, `"- N overs game"` (seen); `"Match tied"`, `"(X won the Super Over)"`, `"No result"`, `"Match abandoned …"`, `"Match drawn"` (assumed). | Provider convention. | **Safety rule:** automated settlement of Match Winner needs `matchEnded === true` AND a confidently parsed result (or `match_info.matchWinner`). Anything else goes to the admin manual-settlement queue. |
| A-13 | `matchType: ""` → infer the format from series fixture counts, then the name; T10 leagues (`/T10/` in name) are a separate `T10` format even though the provider says `t20`. | "Abu Dhabi T10 League" reported as `t20`; India W v Zimbabwe W has `""`. | Wrong format → wrong default lines for O/U markets. Admin can override `format` per match. |
| A-14 | `allapi/apiresult.js` is reference material only. Fixtures are extracted from it with the API key removed. | The file contains the API key in plain text. | `allapi/` is git-ignored. Rotate the key if this folder was ever shared. |
| A-15 | On the free tier (100 hits/day), live data refreshes every ~15–20 min, so in-play markets on real matches are disabled and the in-play experience runs on the ReplayProvider. | `hitsLimit: 100`. | Automatic: raising `CRICAPI_DAILY_HIT_LIMIT` (paid plan) shortens the interval, and in-play turns on once interval ≤ stale threshold. |
| A-16 | `match_squad` and `match_bbb` follow the provider's public docs. `match_info` and `match_scorecard` are now confirmed by real samples (API_CONTRACT §2.11). | The squad sample was empty, and `match_bbb` failed because `bbbEnabled` is false on every match seen. | Lenient schemas + capability flags. Missing capability → the dependent markets are never created, so they can never be mis-settled. |
| A-17 | Under DLS the revised target isn't given. Second-innings O/U lines are settled on actual runs scored; Match Winner is settled on the stated winner only. | `"Austria Women won by 10 wkts (DLS method)"` with 37 vs 39. | Documented in MARKET_RULES (reduced-overs rules void session markets whose overs weren't bowled). |
| A-18 | Replay squads: for teams without a captured squad, deterministic synthetic players are generated and labelled `source: 'replay'`. | Only one series squad was captured. | Replay data never mixes with live data (separate `source` field, and replay matches are flagged in the UI). |
| A-19 | DLS replays: the revised target isn't in the data, so the replay uses the chasing side's actual final score as the target (they reach it on the last ball). Non-DLS chases use first-innings runs + 1. | "Austria Women won by 10 wkts (DLS method)", 37 vs 39. | Replay-only. Live DLS matches settle from the result text (A-17). |
| A-20 | Replay sessions run in both provider modes. `providerMode` only switches *live CricAPI polling* on or off. Replay matches are always tagged `source: 'replay'` and shown as simulated. | Lets in-play markets be demoed while live mode syncs real fixtures. | If strict exclusivity is wanted, the poller can skip replay ticks when `providerMode === 'live'` (one line). |
| A-21 | `match_bbb` field names (`inning`, `over`, `ball`, `batsman`, `bowler`, `runs`, `extras`, `extrasType`, `dismissal`, `playerOut`, `catcher`) and 0-based innings/overs are taken from provider docs. The normalizer detects 0- vs 1-based numbering and recomputes legal-ball counts, crease and running score itself. | No sample (A-16). | Drop one real `match_bbb` response into `allapi/` and the schema gets pinned to it. |
| A-22 | Par (expected first-innings total) comes from history in our own DB: same series (≥2 completed matches), else same venue (≥2), else same format (≥5), else defaults of 10 / 7.8 / 5.6 runs per over for T10 / T20 / ODI. Team strength = smoothed win rate over the last 10 completed matches, head-to-head from the last 10 meetings. | The provider has no odds or ratings. | Better data → better prices. The model is isolated in `markets/odds/probability.ts` and `pricing/context.ts`. |
| A-23 | Line markets (innings total, sessions, next over, fall of wicket, player runs) have a fixed line set at creation; only the odds move. | Keeps one line per market, so settlement and liability are unambiguous. | Indian-style moving fancy lines would mean a new market per line (close old, open new). |
| A-24 | A session market (overs 1–N) stops taking bets when over N, its last, starts. A next-over market stops at that over's first delivery (a wide counts). | Common sportsbook practice; matches the spec's "closes when the over starts". | Change in `pricing/totals.ts` `shouldClose`. |
| A-25 | Test matches: Match Winner (3-way), Toss and Top Batsman/Bowler are offered. In-play Test pricing uses the pre-match model; innings/session line markets aren't created for Tests. | No Test data in the captures; a reliable in-play Test model needs days and overs remaining, which the feed doesn't give. | Add a Test model in `pricing/matchWinner.ts` when real Test data is available. |
| A-26 | An accumulator's full potential return counts against the liability book of every leg's market (and its liability check). | Conservative: the house can never be over-exposed because of an acca. | Accas may hit market liability caps earlier than singles. A correlation-aware split can replace it later. |
| A-27 | Cash out: open singles on Match Winner only, quote valid 10 s, executable once and only while the market is OPEN at the quoted version. Re-submitting a used quote returns the original cash-out (idempotent). | Spec §8. | More market types can be enabled by adding them to `CASHOUT_MARKETS`. |
| A-28 | The in-play bet delay applies only while the match is in progress. Pre-match bets on in-play-capable markets (e.g. Match Winner) are accepted instantly. A delayed bet is rejected if its market was suspended at any point during the delay (a delivery, review…), closed, or its price shortened. | Industry practice against past-posting. | Tune `defaultBetDelayMs` / per-market `betDelayMs`. |
| A-29 | The daily loss limit counts the worst case: today's settled net loss + today's still-open stakes + the new stake. | A loss limit that can be exceeded by open bets wouldn't protect anyone. | — |
| A-30 | Line markets settle as soon as the line is passed (runs only go up), e.g. an innings total's Over wins the moment the score passes it, even if the innings is later cut short. | Standard bookmaker rule; frees locked stakes early. | — |
| A-31 | Top Batsman/Bowler: a selection is void if the player appears in no batting or bowling line of the match. Top Bowler is void when nobody took a wicket; ties on wickets break on fewest runs, then dead heat. | The feed has no explicit playing XI. | If the provider exposes the XI (`match_squad`), use it for participation instead. |
| A-32 | Resettlement reverses every settlement posting of the current round and settles again under new idempotency keys (`settle:<betId>:r<n+1>:*`). Cash-outs and admin-voided bets are final and are not resettled. Balances may go negative when a reversed payout was already spent. | Spec §9. | — |
| A-33 | "Active now" on the admin overview means distinct players with an open `/user` socket right now. | Session records only update on refresh (every 15 minutes), so they can't say who is here this instant. |
| A-34 | House P&L is the net of the `house` ledger account per UTC day: captured stakes minus payouts and cash-outs. Bonuses and admin credits aren't in it. | They come from `bonus_pool` and `admin_mint`, and they're a platform choice, not a betting result. |
| A-35 | "Unusual win rate" compares actual wins with what each bet's odds implied, and flags players 2+ standard deviations above over 10+ settled bets in 30 days. Accumulators count with their combined odds. | Raw win rate would flag anyone backing short favourites. The screen says a lucky run can land here too. |
| A-36 | Admin "reset limits" clears daily stake and loss limits and any pending increase. It leaves cool-offs and self-exclusion alone. | Those are protections the player chose, and an admin tool shouldn't undo them. |
| A-37 | Suspending an account stores its previous status and lifting the suspension restores it. Open bets on a suspended account stay in play and settle normally. | A permanent self-exclusion lives only in `status`, so overwriting it would quietly lift it. Voiding bets would be a separate decision, per bet. |
| A-38 | Admins can't manage other staff, only a superadmin can, and nobody can act on their own account. Any admin can change platform settings. | Matches the existing rule for staff wallets. The spec doesn't restrict settings by role, and every change is audited. |
| A-39 | The seed creates history through the real placement, settlement and ledger services, then moves only the timestamps into the past, using the raw driver. | The services stamp the current time. Amounts, keys and balances stay as written, and the seed fails unless reconciliation is clean. |
| A-40 | Players see plain wording built in the frontend (`gamb/src/lib/market-copy.ts`) from the market type, name and line. The engine, API and admin app keep the original names. Lines end in .5, so Over 145.5 reads "146 or more" and a session Yes reads "55 or more" for line 54.5, which matches settlement. | The user asked for simple English. | A new market type shows its engine name until a question is added there. |
| A-41 | In `replay` mode the public match lists and featured picks leave out real (`source: live`) matches. They stay in the database, the admin app and on direct links, and return when the mode goes back to `live`. | Nothing polls real matches in replay mode, so they freeze as "score delayed" and bets on them could never settle. | A real match already in progress when the mode changes disappears from player lists until the mode changes back. |
